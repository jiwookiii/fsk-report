# 보안 문서 게시

비밀번호로 암호화한 HTML 문서를 GitHub Pages에 게시하고, 로그인한 사람만 조회하게 하는 구성.

## 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 로그인 화면. `data/report.enc.json`을 읽어 아이디·비밀번호로 복호화한 뒤 문서를 표시 |
| `admin.html` | 계정 발급 도구. 원본 HTML을 암호화하고 계정을 발급해 `report.enc.json`을 생성 |
| `data/report.enc.json` | 암호화 데이터(본문 + 계정별 잠금). 문서를 교체할 때 이 파일만 바꿈 |
| `.nojekyll`, `.gitignore` | Pages 설정 및 올리면 안 되는 파일 제외 |

접속 주소: `https://<소유자>.github.io/<저장소>/` (로그인), `…/admin.html` (계정 발급 도구)

## 최초 설정

1. GitHub에서 저장소 생성 후 이 폴더의 파일을 모두 올림(`.nojekyll` 포함).
2. 저장소 Settings → Pages → Source를 "Deploy from a branch", Branch를 `main` / `/(root)`로 지정.
3. 1~2분 뒤 접속 주소에서 로그인 화면이 열리는지 확인.

## 문서 교체·계정 발급 (매월)

1. `admin.html`을 열고 암호화 전 원본 HTML을 선택.
2. 계정 입력. 계정을 그대로 유지하려면 지난번 `계정목록.csv`를 "기존 계정목록 CSV 불러오기"로 불러옴.
3. 게시 설정(소유자·저장소·토큰) 확인. 토큰은 해당 저장소 하나에 Contents 읽기/쓰기만 허용한 fine-grained 토큰(GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens)을 사용. "이 브라우저에 토큰 기억"을 켜면 다음부터 입력 생략.
4. "암호화 후 게시" → 암호화, 계정별 복호화 검증, 저장소 `data/report.enc.json` 교체, 사이트 반영 확인까지 자동 진행. 토큰이 없으면 `report.enc.json`이 내려받아지므로 저장소 `data/` 폴더에 직접 덮어쓰기로 올림.
5. 계정목록 CSV를 내려받아 안전한 곳에 보관하고, 로그인 화면에서 실제 계정으로 열리는지 확인한 뒤 접속 주소와 비밀번호를 서로 다른 경로로 전달.

게시하면 계정 목록이 통째로 교체됨. 새로 만든 데이터에 없는 기존 계정은 그때부터 로그인되지 않음.

## 보안상 한계

- 암호문은 공개 저장소에서 누구나 내려받을 수 있으므로 보안 수준은 비밀번호 강도에 달려 있음. 도구는 12자 미만을 거부하며, 자동 생성(14자 무작위) 사용을 권장.
- 한 번 게시한 암호문은 저장소 이력에 남음. 계정을 빼고 다시 게시해도 이전 게시분은 그 계정의 비밀번호로 계속 열림.
- 원본 HTML과 계정목록 CSV는 저장소에 올리지 말 것. 올린 뒤 삭제해도 이력에 남음.
- 로그인 화면의 문서 제목은 암호화되지 않고 누구에게나 보임.
- 서버가 없는 구조이므로 접속 기록, 로그인 시도 횟수 제한, 계정 즉시 차단 기능은 없음.
- 로그인한 사용자의 화면 캡처·저장은 막을 수 없음(계정별 워터마크로 추적만 가능).

## 암호화 방식

본문은 무작위 256비트 키로 AES-256-GCM 암호화. 그 키를 계정마다 PBKDF2-SHA256(600,000회)로 비밀번호에서 유도한 키로 다시 암호화해 저장. 아이디는 파일별 무작위 솔트를 붙인 SHA-256 해시로만 저장. 처리는 모두 브라우저(Web Crypto) 안에서 이루어짐.
